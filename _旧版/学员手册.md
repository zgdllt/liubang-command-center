# 学员手册：像刘邦一样用 AI

> 第一堂 Agent 管理课 · 一页纸
> 带走三样东西：一张能力卡、一个委托深度、一条可执行验收。

---

## 1. 今天只记一句话

> **AI 让"做"变便宜了，但没有让"验收"变便宜。你能把事委托多深，取决于你能多便宜地验收。**

刘邦说：运筹帷幄不如张良，镇国家、给馈饷不如萧何，连百万之军不如韩信。他能用这三个人，所以取天下。项羽有一个范增，却不能用。

翻译：**你不需要比 AI 强，你需要比它会用人。**

## 2. 五幕，五句话

| 幕 | 一句话 | 你要检查自己 |
|---|---|---|
| 吾不如子房、萧何、韩信 | 管理者的产出是"让谁做成了什么"，不是"我做了多少" | 我是在和 AI 比速度，还是在编排它？ |
| 萧何追韩信 | 识人看当面计划，不看履历；授权要给名分和权威 | 我让 agent 先说过计划吗？ |
| 陈平盗嫂受金 | 用人如器，按长处派活，容忍短处，设计边界 | 我有没有把"聪明但不可靠"的 agent 放在不可逆操作上？ |
| 张良借箸代筹 | 第二意见要在不可逆之前进来；发现错了，改得越便宜越好 | 我的"销印"成本有多高？ |
| 白登之围 | 低置信度的警告最容易被忽略；失败后要改流程，不只改输出 | 我的团队里有没有一个"刘敬"？ |

## 3. 三个工具

### 3.1 能力卡

```text
任务类型：
样本 1：
样本 2：
样本 3：
通过率：
失败模式（按频率排序）：
需要人改的地方：
适用边界（什么情况下不要用它）：
```

四种常见角色：

| 角色 | 特征 | 适合 | 不适合 |
|---|---|---|---|
| 张良型 | 会规划、会分析、慢 | 方案、拆解、复盘 | 大批量执行 |
| 萧何型 | 稳、细、能守 | 数据、账本、流程、验收 | 从零创新 |
| 韩信型 | 执行力强、要授权 | 明确目标的大任务 | 目标模糊、边界不清 |
| 陈平型 | 会找漏洞、路子野 | 红队、对抗、创意 | 不可逆操作 |

### 3.2 委托深度 L1–L4

| 层级 | 你让它做什么 | 你保留什么 | 最低验收方式 |
|---|---|---|---|
| L1 代查 | 搜索、总结、找资料 | 每一条结论的判断 | 来源链接 + 抽检 |
| L2 代写 | 出草稿、出方案 | 结构、语气、事实 | diff + 评分表 |
| L3 代做 | 执行有明确标准的任务 | 验收和异常处理 | 测试/脚本 + 日志 |
| L4 代判 | 在 bounded 领域做判断 | 抽检、异常、最终责任 | 校准数据 + 上报规则 + 回滚 |

> 升一级的前提不是"我更信任它"，而是"我多了一条更便宜的验收"。

### 3.3 验收三件套

| 件 | 问题 | 例子 |
|---|---|---|
| 可执行 | 有没有一条命令/清单能给出 pass/fail？ | `pytest`、`verify.py`、检查表 |
| 可证据 | 它说做完了，我凭什么信？ | 日志、diff、引用、截图 |
| 可回退 | 做错了，我能不能低成本撤回？ | git、备份、权限、人工闸门 |

三件缺一件，委托深度就要降一级。

## 4. 实验规则

### A 萧何的粮道（15 分钟，个人）

- 打开 `lab/solo`，读 `README.md` 和 `ACCEPTANCE.md`。
- 用你自己的 agent 修 `granary.py`。
- 你可以让 agent 做任何事；但提交时，你要为结果签字。
- 提交：把 `granary.py` 和 `criteria.md` 放到 `submissions/<你的名字>/`。
- 计分：隐藏验收 10 分 + 验收清单覆盖 6 分。

**提示**：可见测试全部通过，不代表客户验收通过。你给 agent 的 brief 里写了什么，它就会优化什么。

### B 汉营（20–25 分钟，4 人）

- 4 个角色：张良（情报）、萧何（粮草）、韩信（行军）、周勃（城门）。
- 每人只改自己的文件；`contract.md`（军令）是唯一真相。
- 本地测试可能是上一任留下的，可能和军令不一致。
- 集成：队长运行 `python3 verify.py`。
- 计分：6 个场景 × 2 分；找出军令冲突额外 3 分。

**提示**：先一起读军令，再各自跑测试。局部绿 ≠ 系统绿。

### C 白登（15–20 分钟，2–6 人）

- 你被围在白登山，5 轮突围。
- 每轮：收到斥候回报 → 用 agent 提交"方向 + 置信度" → 全队讨论 → 主将提交最终方向 → 揭晓。
- 每人每局 2 次复探，可以花一次确认探报可信度（80% 准确）。
- 个人分看校准，不看胜率。
- 计分：团队 +10/−5；个人校准分 0–100。

**提示**：置信度是校准数据，不是气势。虚报 100 会让你在复盘时被点名。

---

## 5. 复盘问题

1. 你在哪一步把"我觉得对"当成了验收？
2. 你的 agent 在哪一步"自信地错"？你当时为什么信了它？
3. 如果重来一次，你会把哪一条验收标准写进 brief？

---

## 6. 作业

选一个你本周最常做的任务，写一份 `ACCEPTANCE.md`，不超过一页：

- [ ] 3 条可执行检查（命令、脚本或清单）
- [ ] 1 条证据要求（日志、引用、diff、截图）
- [ ] 1 条回退方案（版本、备份、权限、人工闸门）

用你的 agent 跑一遍，记录它第一次失败在哪。下次带三样东西：验收标准、失败记录、你的能力卡。
