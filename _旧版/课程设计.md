# 像刘邦一样用 AI：第一堂 Agent 管理课

> 课程包版本：v1（2026-11-24）
> 标准时长：90 分钟；扩展版：120 分钟
> 配套实验：`lab/`，三条路线，可单人、可组队、可多人游戏
> 定位：线下工作坊 / 直播课 / 社团内训的第一讲

---

## 0. 一页纸

**一句话**：AI 让"做"变便宜了，但没有让"验收"变便宜。你能把事委托多深，取决于你能多便宜地验收。

**刘邦的作用**：他不是"最强执行者"的榜样，而是"最强编排者"的样本。《史记·高祖本纪》里他自己说：

> 夫运筹策帷帐之中，决胜于千里之外，吾不如子房；镇国家，抚百姓，给馈饷，不绝粮道，吾不如萧何；连百万之军，战必胜，攻必取，吾不如韩信。此三者，皆人杰也，吾能用之，此吾所以取天下也。项羽有一范增而不能用，此其所以为我擒也。

翻译成今天的话：**你不需要比 AI 强，你需要比它会用人。**

**三个动作**：

1. **识人**：用任务分布看能力，不用名气、榜单、demo。
2. **用人如器**：按长处派活，容忍短处，设计边界。
3. **从谏与验收**：让独立意见进来，发现错了能低成本改；把"我觉得行"变成"跑一遍就知道行不行"。

**三个实验**：

| 站点 | 任务 | 练什么 | 时长 |
|---|---|---|---|
| A 萧何的粮道 | 修好粮草分配器，通过监军验收 | 验收标准的质量决定 agent 的产出 | 15 min |
| B 汉营 | 4 人各写一个模块，按军令集成 | 接口契约是可执行验收；局部绿 ≠ 系统绿 | 20–25 min |
| C 白登 | 2–6 人，每人一个 agent，5 轮突围 | 自信 ≠ 正确；复探有成本；异议通道 | 15–20 min |

**课后作业**：给你本周最常做的一个任务写一份 `ACCEPTANCE.md`，不超过一页，包含 3 条可执行检查、1 条证据要求、1 条回退方案。

## 1. 课程定位

### 1.1 这不是什么

- 不是 prompt 技巧课。技巧会过期，验收标准不会。
- 不是工具教程。今天讲 Claude Code，明天可能是另一个 harness；管理动作是跨工具的。
- 不是"AI 会不会取代人"的预测课。这个问题在课堂上无法验证，讲了也没有可执行结论。
- 不是成功学。刘邦也打过败仗，白登之围差点回不来；这堂课不回避这一点。

### 1.2 这是什么

一门关于**委托与验收**的课。它假设：

- 听众已经在用 AI，但大多数时候停在"工具"层面：自己操作、自己改、自己兜底。
- 听众接下来会把更长的任务交给 agent：写代码、做研究、跑实验、写材料。
- 委托越深，返工越贵；返工越贵，人越不敢委托。这个循环要靠"验收能力"打破。

### 1.3 与后续七集的关系

这堂课是入口，不替代后续七集。它先建立三个共同语言（识人、用人、验收），后面每集拆一个：

| 后续 | 主题 | 与第一堂的接口 |
|---|---|---|
| 第 2 集 | 授权深度 = 验收成本 | 把 L1–L4 展开成可操作的委托层级 |
| 第 3 集 | 写验收标准就是新的"会干活" | 把"验收三件套"展开成规格编译 |
| 第 4 集 | 它不会因为被信任而成长 | 解释为什么"刘邦式信任"在 agent 上失效 |
| 第 5 集 | 断掉的学徒阶梯 | 人怎么通过"摸高"长判断力 |
| 第 6 集 | 自信地错 | 校准：置信度不等于正确率 |
| 第 7 集 | 要"长出来"的员工是你自己 | 回到第一堂的问题：你站在哪里 |

## 2. 学习目标

听完这堂课，听众应该能做到：

1. 用自己的话解释：为什么 AI 越强，验收反而越贵。
2. 给自己的一个真实任务定委托深度（L1 代查 / L2 代写 / L3 代做 / L4 代判），并说出下一级需要什么验收能力。
3. 写出至少 3 条可执行的验收标准，而不是"看起来对"。
4. 在实验里记录一次 agent 失败，并定位失败发生在识人、用人、验收的哪一环。
5. 说出一个自己正在重演的"项羽式错误"：能力强、亲自上、不信人、不用人。

**不要求**：会写代码、会搭 agent、会调模型。实验 C 可以纯人工玩；实验 A/B 可以两人一组，一人操作、一人记录。

## 3. 核心命题

### 3.1 成本结构变了

| 环节 | 工业时代 | AI 时代 |
|---|---|---|
| 做 | 贵 | 几乎免费 |
| 说清楚要做什么 | 中 | 变贵了（因为可以做的事变多了） |
| 判断做得对不对 | 中 | **更贵了**（因为产出变多、变快、变得更像对的） |
| 承担后果 | 人 | 仍然是人 |

AI 把第一行打下来了，把第三行推上去了。于是瓶颈从"执行力"移到"判断力"。

### 3.2 委托深度由验收成本决定

同样一个 agent，你可以让它查资料、写草稿、改代码、做判断。四件事的风险不一样，因为验收成本不一样：

- 查资料：你扫一眼来源就能验，成本低，可以深委托。
- 写草稿：你读一遍就知道好坏，成本中，可以中委托。
- 改代码：你要跑测试、看 diff、想边界，成本高，需要工具。
- 做判断：你要有校准数据、异常上报、回滚机制，成本最高，只能 bounded 委托。

**结论**：不是"越信任越要放权"，而是"越验得起越要放权"。验不起的地方，AI 的速度没有价值。

### 3.3 刘邦的镜子

刘邦会识人（萧何追韩信、设坛拜将）、敢授权（韩信连百万之军）、能听劝（张良借箸代筹，他辍食吐哺、立刻销印）。但他也打过败仗：白登之围，不听刘敬，被围七日。

刘邦的强，不在"他比谁强"，在"他能让比他强的人为他所用，并且在证据面前改得快"。

AI 不会因为你的信任而成长，也不会因为你的情义而忠诚。所以：

> 学刘邦的识人和授权，补上他的验收。你唯一不能外包的，是最后那句："这算不算干成了？"

## 4. 五幕讲古：刘邦的用人术

> 讲法：每幕先讲一个具体场景，再停 20 秒，让听众在卡片上写"我最近一次类似的委托"。不要先讲道理，先让他们看见自己。

### 4.1 第一幕：吾不如子房、萧何、韩信

**场景**：《史记·高祖本纪》记刘邦称帝后，在洛阳南宫置酒，问群臣"吾所以有天下者何？项氏之所以失天下者何？"然后说了那段"吾不如"的话。他不是谦虚，他是在定义自己的工作：**我的工作不是比他们强，是让他们为我所用。**

**管理动作**：管理者的产出不是"我做了多少"，是"我让谁做成了什么"。

**Agent 对应**：

- 你不需要比 AI 会写代码、会写文章、会做分析；你需要比它会定义问题、分配任务、验收结果。
- 如果你每天的工作是"和 AI 比谁写得快"，你用的是项羽的模式：个人能力很强，但没有组织。
- 如果你每天的工作是"把任务拆给合适的 agent，然后验收"，你用的是刘邦的模式。

**现场提问**：你上一次用 AI，是把它当"更快的自己"，还是当"一个需要被管理的团队"？

**收束**：**刘邦的团队是一个多 agent 系统；项羽是一个单体模型。你用的是哪一个？**

---

### 4.2 第二幕：萧何追韩信——识人、授权、先问计划

**场景**：《史记·淮阴侯列传》记，韩信在项羽手下"官不过郎中，位不过执戟"，多次献策不用，于是投汉。到汉后也不得重用，逃走。萧何听说，来不及报告，亲自去追。刘邦以为萧何也跑了，又怒又急。萧何回来，说："诸将易得耳。至如信者，国士无双。"刘邦说："吾为公以为将。"萧何说："虽为将，信必不留。"刘邦说："以为大将。"萧何说："幸甚。"于是刘邦"择良日，斋戒，设坛场，具礼"，正式拜将。

拜将之后，刘邦问韩信："丞相数言将军，将军何以教寡人计策？"韩信先谢，然后问："今东乡争权天下，岂非项王邪？"刘邦说："然。"韩信于是分析项羽：匹夫之勇、妇人之仁、不能任属贤将、有功当封爵者"印刓敝，忍不能予"——这就是"汉中对"。

**管理动作**：

1. **识人**：韩信没有履历，只有萧何的背书和一次当面策对。刘邦信的是"国士无双"的判断 + 当面计划，不是简历。
2. **授权**：设坛拜将，给的是名分、仪式、权威，不只是任务。
3. **先问计划**：拜将之后第一件事不是"你去打"，是"将军何以教寡人计策"。

**Agent 对应**：

- 选 agent，不要只看榜单；让它在你的任务上说一遍计划，问它"你打算怎么打、哪里不确定、失败了怎么回滚"。
- 给 agent 一个"坛"：清楚的角色、权限、输出格式、验收标准。没有名分的授权，执行时会走样。
- 韩信后来被夺兵权、徙封、最终被杀——授权要有回收机制，但回收机制本身也要有边界。这是下一讲的题目。

**现场提问**：你有没有因为一个 agent 在一次 demo 里表现好，就把一整类任务交给它？你有没有让它先说过计划？

**收束**：**能力卡比印象可靠；拜将之前，先问对策。**

---

### 4.3 第三幕：陈平盗嫂受金——用人如器

**场景**：《史记·陈丞相世家》记，陈平从项羽那边来投，有人告他"盗其嫂"，又告他"受诸将金，金多者善处，金少者恶处"。刘邦责问。陈平说：我裸身来投，不受金没有经费；我的计策如果有用，你就用；如果没用，金都在，我封还官，请辞。刘邦"乃谢，厚赐，拜为护军中尉"。

后来陈平献的都是"奇计"：离间项羽和范增、荥阳突围、伪游云梦擒韩信。这些计策不堂堂正正，但有用。

**管理动作**：**用人如器。** 你要的是这个器在这个任务上的功能，不是它的道德完美。短处要看得见，边界要设计好。

**Agent 对应**：

- 不同 agent 有不同"性格"：有的稳、有的快、有的会胡说、有的会过度自信。按任务选，不按"哪个最好"选。
- 让一个"聪明但不可靠"的 agent 做创意、找漏洞、做红队，可以；让它直接碰不可逆操作，不行。
- 你不需要喜欢它，你需要知道它的失败模式，并把它放在合适的边界里。

**现场提问**：你有没有因为一个 agent"风格不对"就弃用，却没试过把它放在它擅长的任务上？

**收束**：**没有最好的 agent，只有最合适的编排。**

---

### 4.4 第四幕：张良借箸代筹——第二意见与便宜的回滚

**场景**：《史记·留侯世家》记，郦食其劝刘邦复立六国后世，刘邦说"善，趣刻印，先生因行佩之矣"——印都刻好了。张良来见，刘邦把这事告诉他。张良问："谁为陛下画此计者？陛下事去矣。"刘邦问："何哉？"张良借刘邦面前的筷子（"臣请藉前箸为大王筹之"），一条一条数了八个"不可"。刘邦听完，"辍食吐哺，骂曰：'竖儒，几败而公事！'令趣销印。"——饭吐出来，骂人，立刻销印。

**管理动作**：**在不可逆之前，让独立意见进来；发现错了，改得越便宜越好。** 张良不是"反对派"，他是"第二意见"；刘邦不是"没主见"，他是"回滚成本低"。

**Agent 对应**：

- 一个 agent 说"行"，不等于行。让它出一个方案，再让另一个 agent（或你自己）专门找反例。
- 把"销印"做成流程：版本控制、草稿、沙箱、人工闸门。改起来越便宜，你越敢让 agent 跑。
- "从谏如流"在 AI 时代的版本是：**CI 红灯就回滚，不要解释。**

**现场提问**：你有没有过一次"印都刻好了"才发现方案不对？你当时是改，还是硬着头皮上？

**收束**：**验收的核心不是"检查"，是"改得起"。**

---

### 4.5 第五幕：白登之围——不听刘敬的代价

**场景**：《史记·刘敬叔孙通列传》记，刘邦要击匈奴，派刘敬出使。刘敬回来说：两国相击，本该夸耀武力，我只看到老弱和瘦马，这一定是"欲见短，伏奇兵以争利"，匈奴不可击。刘邦大怒，骂他"齐虏！以口舌得官，今乃妄言沮吾军"，把他关起来，亲自率军北上，结果在平城白登被围七日，靠陈平的秘计才脱身。回来后，刘邦"赦刘敬，曰：'吾不用公言，以困平城。'乃封敬二千户，为关内侯。"

**管理动作**：

1. **异议通道**：低置信度的警告，往往是你最不想听的。如果你的验收层只确认你已有的判断，它不是验收，是回音壁。
2. **失败后的流程修复**：刘邦回来后不是只收拾战场，他放了刘敬、认错、封赏。这比"下次注意"有用。
3. **别让"多数"替代"证据"**：刘邦的多数将领都说匈奴可击，刘敬一个人说不可。多数不是验收。

**Agent 对应**：

- 你的 agent 团队里要有一个"刘敬"：专门说"可能不对"的那个。可以是另一个模型、一个红队 prompt、一个检查脚本。
- 当所有 agent 都说"没问题"时，问一句："如果错了，最可能错在哪？"
- 失败后，不要只改输出；改那个让警告被忽略的流程。

**现场提问**：你身边有没有一个"刘敬"？他说话不好听，置信度不高，但他可能是对的。你上一次听他的建议是什么时候？

**收束**：**刘邦赢了项羽，不是因为他从不犯错，是因为他犯错后改得快；白登之围的教训，不是"要听劝"，是"要给劝留一条能进来的路"。**

### 4.6 一张映射表

| 刘邦的瞬间 | 他做对了什么 | 他漏了什么 | Agent 管理动作 | 典型失败 |
|---|---|---|---|---|
| 吾不如子房/萧何/韩信 | 承认自己不是最强，把舞台让给专家 | 没有制度化的验收 | 定义问题 + 分配 + 验收 | 亲自和 AI 比写代码 |
| 萧何追韩信 / 设坛拜将 | 为关键能力付搜索成本；给名分和权威；先问计划 | 韩信的忠诚没有制度保障 | 选型 + 授权 + 先让对方说计划 | 看履历/榜单选型；一句话 brief |
| 陈平盗嫂受金 | 用人如器，按长处派活，容忍短处 | 没有边界就会反噬 | 按任务选模型；设计沙箱 | 让"聪明但不可靠"的 agent 碰不可逆操作 |
| 张良借箸代筹 | 听独立意见，发现错了立刻改 | 如果张良不在，计划就执行了 | 第二意见 + 便宜的回滚 | 一个 agent 说行就执行 |
| 白登之围 | 失败后认错、释放并封赏刘敬 | 事前不听低置信度警告 | 异议通道 + 异常上报 + 流程修复 | 验收只确认自己已有的判断 |
| 约法三章 | 用三条硬规则约束行为 | 规则太简，边界情况靠人 | 权限/护栏/检查清单 | 给 agent 一百页 policy，一条也没执行 |

> 说明：白登一幕留给实验 C 的复盘用。游戏里会出现"项羽时刻"（置信度高但判断错）和"刘敬时刻"（置信度低但判断对），复盘时对照这两个时刻，比讲道理有效。

## 5. 三个工具

### 5.1 能力卡（Capability Card）

不要问"这个 agent 行不行"，问"它在这类任务上的失败模式是什么"。

```text
任务类型：
样本 1：
样本 2：
样本 3：
通过率：
失败模式（按频率排序）：
需要人改的地方：
适用边界（什么情况下不要用它）：
```

用法：同一类任务跑 3 个样本，记录通过/失败/人改了什么。三次之后，你对它的判断比任何榜单都准。

**四种常见"角色"**（借刘邦的团队做记忆钩子）：

| 角色 | 特征 | 适合 | 不适合 |
|---|---|---|---|
| 张良型 | 会规划、会分析、慢 | 方案、拆解、复盘 | 大批量执行 |
| 萧何型 | 稳、细、能守 | 数据、账本、流程、验收 | 从零创新 |
| 韩信型 | 执行力强、要授权 | 明确目标的大任务 | 目标模糊、边界不清 |
| 陈平型 | 会找漏洞、路子野 | 红队、对抗、创意 | 不可逆操作 |

### 5.2 委托深度四级（L1–L4）

| 层级 | 你让它做什么 | 你保留什么 | 最低验收方式 |
|---|---|---|---|
| L1 代查 | 搜索、总结、找资料 | 每一条结论的判断 | 来源链接 + 抽检 |
| L2 代写 | 出草稿、出方案 | 结构、语气、事实 | diff + 评分表 |
| L3 代做 | 执行有明确标准的任务 | 验收和异常处理 | 测试/脚本 + 日志 |
| L4 代判 | 在 bounded 领域做判断 | 抽检、异常、最终责任 | 校准数据 + 上报规则 + 回滚 |

**规则**：升一级的前提不是"我更信任它"，而是"我多了一条更便宜的验收"。没有新的验收能力，就不要升委托深度。

### 5.3 验收三件套

| 件 | 问题 | 刘邦的例子 | 你的例子 |
|---|---|---|---|

## 7. 实验设计

> 实验目的不是"教会用工具"，是让听众在 15–25 分钟里亲身经历一次"委托—返工—验收"的循环，并在复盘时能用数据说出自己卡在哪。

### 7.1 实验 A：萧何的粮道（单人）

**任务**：修好 `lab/solo/granary.py`，让粮草分配器满足"监军验收"。

**关键设计**：

- 可见测试 `test_visible.py` 全部通过，但隐藏验收 `facilitator/hidden_tests.py` 覆盖优先级、余数、非法输入、确定性等边界。
- 验收标准在 `lab/solo/ACCEPTANCE.md`，不在可见测试里。
- 学员要把"给 agent 的 brief"和"验收清单"写进 `criteria.md` 一起提交。

**它演示什么**：

> 你给 agent 的验收标准，就是它眼里的全部世界。你说"让测试通过"，它就只让测试通过；你没写下的维度，它不会替你想。

**计分**：隐藏测试 10 分 + 验收清单覆盖 6 分 = 16 分。

**复盘数据**：把学员分成两组——"只跑了 pytest"和"把 ACCEPTANCE.md 贴进了 brief"——对比隐藏测试通过率。样本小，只做课堂演示，不做统计推断。

### 7.2 实验 B：汉营（四人一队）

**任务**：4 人各负责一个模块——张良（情报）、萧何（粮草）、韩信（行军）、周勃（城门）——按 `lab/team/contract.md`（军令）集成，通过 `verify.py` 的 6 个端到端场景。

**关键设计**：

- 每个模块的本地测试都通过，但本地测试是上一任留下的，可能和军令不一致。
- 集成失败通常不是"谁写错了"，而是"大家对单位、时间、边界的理解不一致"。
- 军令是唯一真相；本地测试只是参考。

**它演示什么**：

> 局部绿不等于系统绿。接口契约是可执行验收；团队验收的第一步是大家一起读军令，而不是各自跑测试。

**计分**：6 个场景，每个 2 分，共 12 分；额外 3 分给"找出军令与本地测试不一致"的队伍。

**组织方式**：同一张桌子的人共用一个文件夹，各自只改自己的文件；远程队伍各自改完，把 4 个文件发给队长，队长运行 `verify.py`。

### 7.3 实验 C：白登（多人校准游戏）

**任务**：2–6 人，5 轮。你被围在白登山；每轮斥候回报一个可能的薄弱方向；每人用自己的 agent 提交"突围方向 + 置信度"；全队讨论后由主将提交最终方向；裁判揭晓真相并计分。

**关键设计**：

- 每个玩家的斥候可靠度是隐藏的，信号强度（清晰/一般/模糊）只是噪声提示。
- 每人每局有 2 次"复探"，可以花一次确认探报可信度（80% 准确）——验收是有成本的，不能什么都验。
- 个人分不看胜率，看校准分（Brier score）：置信度越接近实际正确率，分越高。
- 会出现两个时刻：
  - **项羽时刻**：置信度 ≥80 但判断错误——"匹夫之勇"式的自信。
  - **刘敬时刻**：置信度 ≤40 但判断正确，而团队没听——"有一范增而不能用"的另一种版本。

**它演示什么**：

> 自信不等于正确。团队决策的第一步不是投票，是搞清楚谁的探报值得信、谁的置信度在通货膨胀，以及那个说"不对"的人有没有被听见。

**计分**：团队分（+10 正确 / −5 错误）+ 个人校准分（0–100）。

**组织方式**：讲师在自己的电脑上运行 `referee.py`，大屏打开 `/board`；学员在自己的电脑上运行 `client.py`，把 `agent_prompt.md` 贴进自己的 agent。没有 agent 的学员可以手动运行 CLI，或两人一组共用一台电脑。

1. 你在哪一步把"我觉得对"当成了验收？

### 8.3 讲师结论（只说一次，不重复）

> 刘邦赢了项羽，不是因为他每一仗都比项羽强。他自己说得很清楚：运筹不如张良，治国不如萧何，打仗不如韩信。他赢在能把这三个人放在对的位置上，并且在张良说"不对"的时候，立刻把印销掉。
>
> 你用 AI，不能假设自己身边有一个张良。你要么自己成为那个能听出"不对"的人，要么把"不对"做成一套谁都能跑的标准。前者靠判断力，后者靠工程。这堂课练的是后者；后续七集，练前者。
>
> 项羽有一范增而不能用。你有一个 agent 团队，你用了吗？

## 10. 风险与边界

| 风险 | 预案 |
|---|---|
| 学员没装 agent | 实验 C 可纯人工玩；实验 A/B 两人一组，一人操作一人记录 |
| 网络不稳 | 实验 A/B 完全离线；实验 C 用局域网 IP，不用公网 |
| 时间超时 | 实验 A 硬性 15 分钟，到点强制提交；实验 C 用固定轮数，不拖堂 |
| 有人作弊（读裁判源码/隐藏测试） | 明说：这是学习游戏，作弊只会让你复盘时无话可说；隐藏测试放在讲师机器上，不随工作区分发 |
| 学员觉得"刘邦"只是噱头 | 每一幕都落到一个可执行动作和一个失败模式；复盘用数据说话，不用典故收尾 |
| 样本太小，数据不显著 | 明说这是课堂演示，不是教育实验；不宣称因果，只展示现象 |
